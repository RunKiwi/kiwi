4 Individual Design Strategies Detailed

Each approach solves a specific aspect of the UX problem.

Strategy 1 Just-in-time

Contextual Model Chip Feedback

Instead of forcing the user to monitor 4 different progress bars, the Model selector chip dynamically changes style based on whether that specific model's tier has quota.

Healthy (< 75%): [ Work: Haiku · Economy ]
Constrained (85%): [ Work: Haiku · ⚠️ 150k left ]
Exhausted (100%): [ Work: Haiku · ⛔ Exhausted ]
✓ Advantage: Zero visual noise until the moment the user selects a constrained model.
Strategy 2 Progressive Disclosure

Unified Allowance Health Pill

Replaces the single agent-minutes gauge with an aggregate status pill. It stays calm when everything has quota, and shows the bottleneck when a limit nears. Hover/click gives the breakdown.

Allowances Healthy · 12/500m
Economy 85% · 120/500m
Economy Exhausted · 120/500m
✓ Advantage: One click provides full transparency across all 3 token tiers and minutes.
Strategy 3 Threshold Triggered

Actionable 1-Click Fallback Banners

When an allowance is exhausted, a plain error message causes frustration. This pattern pairs the alert with instant recovery buttons: "Switch to No-Cost" or "Add Key".

⛔ Economy allowance exhausted until Sep 1
✓ Advantage: Unblocks the user in 1 click without navigating to settings.
Strategy 4 Post-Run Transparency

Task Card Quota Badges

Task cards on the board can display subtle consumption tags, letting users understand what each task actually burned in tokens or minutes.

job_7a8f9c2 SUCCEEDED
Add PostgreSQL connection pool metrics
⚡ 12.4k tokens (Economy) ⏱️ 1.2m
✓ Advantage: Gives clarity into which tasks consume larger token allowances.
