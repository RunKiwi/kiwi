# Prod CI/CD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Automate deploys to the real production environment (GCP project
`kiwi-prod-502913`) on every merge to `main`, replacing the fully-manual
runbook, per `docs/superpowers/specs/2026-08-10-prod-cicd-design.md`.

**Architecture:** A new GitHub Actions workflow `.github/workflows/deploy.yml`
runs `verify → build-and-push → migrate → deploy-api → deploy-orchestrator →
deploy-frontend → refresh-fleet`, sequentially gated with `needs:`. The three
Cloud Run deploys share one reusable workflow
(`.github/workflows/_deploy-cloud-run-canary.yml`) that deploys a `--no-traffic`
canary revision, health-checks it, promotes it to 100% traffic, re-verifies,
and rolls back to the previous revision on any health-check failure. GCP auth
uses Workload Identity Federation (no long-lived key), set up once by a human
via `deploy/gcp/bootstrap-cicd.sh`.

**Tech Stack:** GitHub Actions, `google-github-actions/auth` +
`setup-gcloud`, `docker/build-push-action`, `gcloud` CLI, bash, `jq` (present
by default on `ubuntu-latest` runners).

## Global Constraints

- GCP project: `kiwi-prod-502913`. Region: `us-central1`. Artifact Registry
  repo: `kiwi-repo`. Fleet VM: `kiwi-free-fleet` in zone `us-central1-a`.
- Go version `1.25.0`, Node version `20` (match the existing `ci.yml` /
  `frontend-ci.yml` exactly).
- No service-account JSON key anywhere — GCP auth is Workload Identity
  Federation only.
- The deploy identity (`kiwi-deploy@...`) must be a separate service account
  from the Cloud Run runtime identity (`kiwi-cloudrun-sa@...`) — never reuse
  it.
- Deploys are fully automatic on push to `main` — no manual approval gate.
- Cloud Run services (api/orchestrator/frontend) get automatic rollback on
  health-check failure. The migrate job and the fleet-VM refresh do **not**
  auto-rollback — they fail loudly and stop the pipeline instead (see design
  doc rationale).
- Every merge deploys all components, not path-filtered — deliberately, to
  close the drift bug described in the design doc.
- The frontend build must fail if `secrets.POSTHOG_KEY` is empty — this is a
  known trap (the build arg fails silently, not loudly, when omitted).
- `/healthz` and `/readyz` are registered for every `kiwid` role (verified in
  `ee/orchestrator/server.go`), so the same canary pattern applies uniformly
  to `kiwi-api`, `kiwi-orchestrator`, and `kiwi-frontend`.

### Task 1: Reusable Cloud Run canary-deploy workflow

**Files:**
- Create: `.github/workflows/_deploy-cloud-run-canary.yml`

**Interfaces:**
- Consumes: nothing from other tasks (leaf file).
- Produces: a `workflow_call` reusable workflow with inputs `service`
  (string), `image` (string), `project` (string), `region` (string), `tag`
  (string), and required secrets `workload_identity_provider`,
  `deploy_sa_email`. Task 4 invokes this three times via `uses:
  ./.github/workflows/_deploy-cloud-run-canary.yml`.

- [ ] **Step 1: Write the reusable workflow file**

```yaml
name: Deploy Cloud Run service (canary)

on:
  workflow_call:
    inputs:
      service:
        description: "Cloud Run service name"
        required: true
        type: string
      image:
        description: "Full image reference to deploy, e.g. us-central1-docker.pkg.dev/PROJECT/kiwi-repo/kiwid:SHA"
        required: true
        type: string
      project:
        required: true
        type: string
      region:
        required: true
        type: string
      tag:
        description: "Canary revision tag, must be unique per run"
        required: true
        type: string
    secrets:
      workload_identity_provider:
        required: true
      deploy_sa_email:
        required: true

jobs:
  canary-deploy:
    name: Canary deploy ${{ inputs.service }}
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: read
    steps:
      - name: Authenticate to GCP
        uses: google-github-actions/auth@v2
        with:
          workload_identity_provider: ${{ secrets.workload_identity_provider }}
          service_account: ${{ secrets.deploy_sa_email }}

      - name: Set up gcloud
        uses: google-github-actions/setup-gcloud@v2

      - name: Canary deploy, health-check, promote or roll back
        shell: bash
        env:
          SERVICE: ${{ inputs.service }}
          IMAGE: ${{ inputs.image }}
          PROJECT: ${{ inputs.project }}
          REGION: ${{ inputs.region }}
          TAG: ${{ inputs.tag }}
        run: |
          set -euo pipefail

          check_health() {
            local base_url="$1"
            for attempt in $(seq 1 10); do
              if curl -fsS --max-time 5 "${base_url}/healthz" >/dev/null \
                 && curl -fsS --max-time 5 "${base_url}/readyz" >/dev/null; then
                return 0
              fi
              echo "health check attempt ${attempt}/10 failed for ${base_url}, retrying in 6s..."
              sleep 6
            done
            return 1
          }

          PREV_REVISION=$(gcloud run services describe "$SERVICE" \
            --project "$PROJECT" --region "$REGION" --format=json \
            | jq -r '[.status.traffic[]? | select(.percent==100)] | .[0].revisionName // empty')

          echo "current revision serving 100% traffic: ${PREV_REVISION:-<none>}"

          echo "deploying canary revision, tag=${TAG}, image=${IMAGE}"
          gcloud run deploy "$SERVICE" \
            --project "$PROJECT" --region "$REGION" \
            --image "$IMAGE" \
            --no-traffic \
            --tag "$TAG" \
            --quiet

          CANARY_URL=$(gcloud run services describe "$SERVICE" \
            --project "$PROJECT" --region "$REGION" --format=json \
            | jq -r --arg tag "$TAG" '.status.traffic[] | select(.tag==$tag) | .url')

          if [ -z "$CANARY_URL" ]; then
            echo "::error::could not resolve canary URL for tag ${TAG} on service ${SERVICE}"
            exit 1
          fi

          echo "canary URL: ${CANARY_URL}"

          if ! check_health "$CANARY_URL"; then
            echo "::error::canary revision for ${SERVICE} failed health checks; leaving prod traffic untouched"
            exit 1
          fi

          echo "canary healthy, shifting 100% traffic to the new revision"
          gcloud run services update-traffic "$SERVICE" \
            --project "$PROJECT" --region "$REGION" \
            --to-latest --quiet

          PUBLIC_URL=$(gcloud run services describe "$SERVICE" \
            --project "$PROJECT" --region "$REGION" --format='value(status.url)')

          if check_health "$PUBLIC_URL"; then
            echo "deploy of ${SERVICE} succeeded"
            exit 0
          fi

          echo "::error::${SERVICE} failed health checks after traffic cutover"

          if [ -z "$PREV_REVISION" ]; then
            echo "::error::no previous revision recorded, cannot auto-rollback ${SERVICE}; manual intervention required"
            exit 1
          fi

          echo "rolling back ${SERVICE} to ${PREV_REVISION}"
          gcloud run services update-traffic "$SERVICE" \
            --project "$PROJECT" --region "$REGION" \
            --to-revisions "${PREV_REVISION}=100" --quiet
          exit 1
```

### Task 2: `deploy.yml` — verify and build-and-push jobs

**Files:**
- Create: `.github/workflows/deploy.yml`

**Interfaces:**
- Consumes: nothing from other tasks yet.
- Produces: job `verify` (no outputs). Job `build-and-push`, `needs:
  verify`, with output `sha` (the 12-char short git SHA used to tag every
  image). Later tasks reference this as
  `needs.build-and-push.outputs.sha`. Workflow-level `env:` keys `GCP_PROJECT`,
  `GCP_REGION`, `ARTIFACT_REPO`, `FLEET_VM_NAME`, `FLEET_VM_ZONE` — later
  tasks reuse these exact names.

- [ ] **Step 1: Write the workflow file with the verify and build-and-push jobs**

```yaml
name: Deploy to Production

on:
  push:
    branches: [ main ]
  workflow_dispatch: {}

env:
  GCP_PROJECT: kiwi-prod-502913
  GCP_REGION: us-central1
  ARTIFACT_REPO: us-central1-docker.pkg.dev/kiwi-prod-502913/kiwi-repo
  FLEET_VM_NAME: kiwi-free-fleet
  FLEET_VM_ZONE: us-central1-a

jobs:
  verify:
    name: Verify (test + lint)
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Go
        uses: actions/setup-go@v5
        with:
          go-version: '1.25.0'
          cache: true

      - name: Go vet
        run: go vet ./...

      - name: Go format check
        run: |
          if [ -n "$(gofmt -l .)" ]; then
            echo "The following files are not formatted correctly. Please run 'go fmt ./...':"
            gofmt -l .
            exit 1
          fi

      - name: Go test
        run: CGO_ENABLED=0 go test ./pkg/...

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
          cache-dependency-path: frontend/package-lock.json

      - name: Frontend install
        working-directory: frontend
        run: npm ci

      - name: Frontend lint
        working-directory: frontend
        run: npm run lint

      - name: Frontend build
        working-directory: frontend
        run: npm run build
        env:
          NEXT_PUBLIC_KIWI_API_URL: https://api.runkiwi.dev

  build-and-push:
    name: Build and push images
    needs: verify
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: read
    outputs:
      sha: ${{ steps.sha.outputs.short }}
    steps:
      - uses: actions/checkout@v4

      - name: Short SHA
        id: sha
        run: echo "short=${GITHUB_SHA::12}" >> "$GITHUB_OUTPUT"

      - name: Require POSTHOG_KEY secret
        run: |
          if [ -z "${{ secrets.POSTHOG_KEY }}" ]; then
            echo "::error::secrets.POSTHOG_KEY is empty; the frontend build would silently ship without analytics. Set it in repo settings before deploying."
            exit 1
          fi

      - name: Authenticate to GCP
        uses: google-github-actions/auth@v2
        with:
          workload_identity_provider: ${{ secrets.GCP_WORKLOAD_IDENTITY_PROVIDER }}
          service_account: ${{ secrets.GCP_DEPLOY_SA_EMAIL }}

      - name: Set up gcloud
        uses: google-github-actions/setup-gcloud@v2

      - name: Configure Docker for Artifact Registry
        run: gcloud auth configure-docker ${{ env.GCP_REGION }}-docker.pkg.dev --quiet

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Build and push kiwid
        uses: docker/build-push-action@v5
        with:
          context: .
          file: Dockerfile
          target: kiwid
          platforms: linux/amd64
          push: true
          tags: |
            ${{ env.ARTIFACT_REPO }}/kiwid:${{ steps.sha.outputs.short }}

      - name: Build and push kiwidaemon
        uses: docker/build-push-action@v5
        with:
          context: .
          file: Dockerfile
          target: kiwidaemon
          platforms: linux/amd64
          push: true
          tags: |
            ${{ env.ARTIFACT_REPO }}/kiwidaemon:${{ steps.sha.outputs.short }}
            ${{ env.ARTIFACT_REPO }}/kiwidaemon:latest

      - name: Build and push frontend
        uses: docker/build-push-action@v5
        with:
          context: frontend
          file: frontend/Dockerfile
          platforms: linux/amd64
          push: true
          build-args: |
            NEXT_PUBLIC_KIWI_API_URL=https://api.runkiwi.dev
            NEXT_PUBLIC_POSTHOG_KEY=${{ secrets.POSTHOG_KEY }}
            NEXT_PUBLIC_POSTHOG_HOST=${{ vars.POSTHOG_HOST }}
          tags: |
            ${{ env.ARTIFACT_REPO }}/frontend:${{ steps.sha.outputs.short }}
```

**Interfaces:**

- [ ] **Step 1: Append the three canary-deploy jobs and the refresh-fleet job**

Add these jobs to the `jobs:` map in `.github/workflows/deploy.yml`, after
`migrate`:

```yaml
  deploy-api:

    uses: ./.github/workflows/_deploy-cloud-run-canary.yml

      workload_identity_provider: ${{ secrets.GCP_WORKLOAD_IDENTITY_PROVIDER }}
      deploy_sa_email: ${{ secrets.GCP_DEPLOY_SA_EMAIL }}

  deploy-orchestrator:
    name: Deploy kiwi-orchestrator
    needs: [deploy-api, build-and-push]
    uses: ./.github/workflows/_deploy-cloud-run-canary.yml
    with:
      service: kiwi-orchestrator
      image: us-central1-docker.pkg.dev/kiwi-prod-502913/kiwi-repo/kiwid:${{ needs.build-and-push.outputs.sha }}
      project: kiwi-prod-502913
      region: us-central1
      tag: canary-${{ needs.build-and-push.outputs.sha }}
    secrets:
      workload_identity_provider: ${{ secrets.GCP_WORKLOAD_IDENTITY_PROVIDER }}
      deploy_sa_email: ${{ secrets.GCP_DEPLOY_SA_EMAIL }}

  deploy-frontend:
    name: Deploy kiwi-frontend
    needs: [deploy-orchestrator, build-and-push]
    uses: ./.github/workflows/_deploy-cloud-run-canary.yml
    with:
      service: kiwi-frontend
      image: us-central1-docker.pkg.dev/kiwi-prod-502913/kiwi-repo/frontend:${{ needs.build-and-push.outputs.sha }}
      project: kiwi-prod-502913
      region: us-central1
      tag: canary-${{ needs.build-and-push.outputs.sha }}
    secrets:
      workload_identity_provider: ${{ secrets.GCP_WORKLOAD_IDENTITY_PROVIDER }}
      deploy_sa_email: ${{ secrets.GCP_DEPLOY_SA_EMAIL }}

  refresh-fleet:
    name: Refresh free-fleet daemon image
    needs: [deploy-frontend, build-and-push]
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: read
    steps:
      - name: Authenticate to GCP
        uses: google-github-actions/auth@v2
        with:
          workload_identity_provider: ${{ secrets.GCP_WORKLOAD_IDENTITY_PROVIDER }}
          service_account: ${{ secrets.GCP_DEPLOY_SA_EMAIL }}

      - name: Set up gcloud
        uses: google-github-actions/setup-gcloud@v2

      - name: Restart fleet daemon-image + provisioner services, verify digest
        env:
          EXPECTED_IMAGE: ${{ env.ARTIFACT_REPO }}/kiwidaemon:${{ needs.build-and-push.outputs.sha }}
        run: |
          set -euo pipefail

          EXPECTED_DIGEST=$(gcloud artifacts docker images describe "$EXPECTED_IMAGE" \
            --format='value(image_summary.digest)')
          echo "expecting fleet host to be running digest: ${EXPECTED_DIGEST}"

          REMOTE_OUTPUT=$(gcloud compute ssh "${{ env.FLEET_VM_NAME }}" \
            --project "${{ env.GCP_PROJECT }}" --zone "${{ env.FLEET_VM_ZONE }}" \
            --tunnel-through-iap \
            --command 'sudo systemctl start kiwi-daemon-image.service && \
                       sudo systemctl restart kiwi-provisioner.service && \
                       echo "DAEMON_IMAGE_STATUS=$(systemctl is-active kiwi-daemon-image.service)" && \
                       echo "PROVISIONER_STATUS=$(systemctl is-active kiwi-provisioner.service)" && \
                       echo "DIGEST=$(sudo docker image inspect kiwidaemon:latest --format "{{index .RepoDigests 0}}")"')

          echo "$REMOTE_OUTPUT"

          PROVISIONER_STATUS=$(echo "$REMOTE_OUTPUT" | grep -o 'PROVISIONER_STATUS=.*' | cut -d= -f2)
          ACTUAL_DIGEST=$(echo "$REMOTE_OUTPUT" | grep -o 'DIGEST=.*@sha256:[a-f0-9]*' | grep -o 'sha256:[a-f0-9]*')

          if [ "$PROVISIONER_STATUS" != "active" ]; then
            echo "::error::kiwi-provisioner.service is not active after refresh on ${{ env.FLEET_VM_NAME }}; manual intervention required"
            exit 1
          fi

          if [ "$ACTUAL_DIGEST" != "$EXPECTED_DIGEST" ]; then
            echo "::error::fleet host kiwidaemon:latest digest (${ACTUAL_DIGEST}) does not match the digest just pushed (${EXPECTED_DIGEST}); manual intervention required on ${{ env.FLEET_VM_NAME }}"
            exit 1
          fi

          echo "fleet host refreshed and verified at digest ${ACTUAL_DIGEST}"
```

### Task 5: One-time GCP bootstrap script (WIF + deploy service account)

**Files:**
- Create: `deploy/gcp/bootstrap-cicd.sh`

**Interfaces:**
- Consumes: nothing from other tasks (standalone operator script — not
  invoked by CI, run once by a human).
- Produces: prints the two values (`GCP_WORKLOAD_IDENTITY_PROVIDER`,
  `GCP_DEPLOY_SA_EMAIL`) that must be set as GitHub Actions secrets for the
  workflows from Tasks 1-4 to authenticate.

- [ ] **Step 1: Write the bootstrap script**

```bash
#!/usr/bin/env bash
# One-time GCP setup for the deploy.yml CI/CD pipeline: creates a Workload
# Identity Federation pool/provider trusting GitHub Actions, a dedicated
# deploy service account (separate from the kiwi-cloudrun-sa runtime
# identity), and grants it exactly the permissions deploy.yml needs. Run
# once, by a human with sufficient IAM in the real project. Not invoked by
# CI. See docs/superpowers/specs/2026-08-10-prod-cicd-design.md.
set -euo pipefail

PROJECT_ID="${PROJECT_ID:-kiwi-prod-502913}"
REGION="${REGION:-us-central1}"
GITHUB_REPO="${GITHUB_REPO:?set GITHUB_REPO to e.g. RunKiwi/kiwi}"
POOL_ID="${POOL_ID:-github-deploy-pool}"
PROVIDER_ID="${PROVIDER_ID:-github-deploy-provider}"
DEPLOY_SA_NAME="${DEPLOY_SA_NAME:-kiwi-deploy}"
DEPLOY_SA_EMAIL="${DEPLOY_SA_NAME}@${PROJECT_ID}.iam.gserviceaccount.com"
FLEET_VM_NAME="${FLEET_VM_NAME:-kiwi-free-fleet}"
FLEET_VM_ZONE="${FLEET_VM_ZONE:-us-central1-a}"
ARTIFACT_REPO="${ARTIFACT_REPO:-kiwi-repo}"

echo "==> Enabling required APIs"
gcloud services enable iamcredentials.googleapis.com sts.googleapis.com \
  --project "$PROJECT_ID"

echo "==> Creating deploy service account (if it doesn't already exist)"
if ! gcloud iam service-accounts describe "$DEPLOY_SA_EMAIL" --project "$PROJECT_ID" >/dev/null 2>&1; then
  gcloud iam service-accounts create "$DEPLOY_SA_NAME" \
    --project "$PROJECT_ID" \
    --display-name "Kiwi CI/CD deploy identity (GitHub Actions)"
fi

echo "==> Creating Workload Identity Pool"
if ! gcloud iam workload-identity-pools describe "$POOL_ID" --project "$PROJECT_ID" --location global >/dev/null 2>&1; then
  gcloud iam workload-identity-pools create "$POOL_ID" \
    --project "$PROJECT_ID" --location global \
    --display-name "GitHub Actions deploy pool"
fi

echo "==> Creating Workload Identity Provider, restricted to ${GITHUB_REPO} on main"
if ! gcloud iam workload-identity-pools providers describe "$PROVIDER_ID" \
    --project "$PROJECT_ID" --location global --workload-identity-pool "$POOL_ID" >/dev/null 2>&1; then
  gcloud iam workload-identity-pools providers create-oidc "$PROVIDER_ID" \
    --project "$PROJECT_ID" --location global --workload-identity-pool "$POOL_ID" \
    --display-name "GitHub Actions OIDC" \
    --attribute-mapping "google.subject=assertion.sub,attribute.repository=assertion.repository,attribute.ref=assertion.ref" \
    --attribute-condition "assertion.repository == '${GITHUB_REPO}' && assertion.ref == 'refs/heads/main'" \
    --issuer-uri "https://token.actions.githubusercontent.com"
fi

POOL_NUMBER=$(gcloud iam workload-identity-pools describe "$POOL_ID" \
  --project "$PROJECT_ID" --location global --format='value(name)')

echo "==> Allowing the pool to impersonate the deploy service account"
gcloud iam service-accounts add-iam-policy-binding "$DEPLOY_SA_EMAIL" \
  --project "$PROJECT_ID" \
  --role "roles/iam.workloadIdentityUser" \
  --member "principalSet://iam.googleapis.com/${POOL_NUMBER}/attribute.repository/${GITHUB_REPO}"

echo "==> Granting Cloud Run deploy permissions"
for SERVICE in kiwi-api kiwi-orchestrator kiwi-frontend; do
  gcloud run services add-iam-policy-binding "$SERVICE" \
    --project "$PROJECT_ID" --region "$REGION" \
    --member "serviceAccount:${DEPLOY_SA_EMAIL}" \
    --role "roles/run.developer"
done

echo "==> Granting Cloud Run job (migrate) permissions"
gcloud run jobs add-iam-policy-binding kiwi-migrate \
  --project "$PROJECT_ID" --region "$REGION" \
  --member "serviceAccount:${DEPLOY_SA_EMAIL}" \
  --role "roles/run.developer"

echo "==> Granting Artifact Registry push permissions"
gcloud artifacts repositories add-iam-policy-binding "$ARTIFACT_REPO" \
  --project "$PROJECT_ID" --location "$REGION" \
  --member "serviceAccount:${DEPLOY_SA_EMAIL}" \
  --role "roles/artifactregistry.writer"

echo "==> Granting IAP tunnel + OS Login access, scoped to the fleet VM only"
gcloud compute instances add-iam-policy-binding "$FLEET_VM_NAME" \
  --project "$PROJECT_ID" --zone "$FLEET_VM_ZONE" \
  --member "serviceAccount:${DEPLOY_SA_EMAIL}" \
  --role "roles/iap.tunnelResourceAccessor"

gcloud compute instances add-iam-policy-binding "$FLEET_VM_NAME" \
  --project "$PROJECT_ID" --zone "$FLEET_VM_ZONE" \
  --member "serviceAccount:${DEPLOY_SA_EMAIL}" \
  --role "roles/compute.osLogin"

echo
echo "==> Done. Add these as GitHub Actions repo secrets:"
echo "GCP_WORKLOAD_IDENTITY_PROVIDER=${POOL_NUMBER}/providers/${PROVIDER_ID}"
echo "GCP_DEPLOY_SA_EMAIL=${DEPLOY_SA_EMAIL}"
echo
echo "Also set POSTHOG_KEY (from frontend/.env.local) as a repo secret."
```

## Continuous Deployment

Steps 1 and 4 of the runbook above ("Build and Push Images" and re-running
`gcloud run deploy` for a new version) are automated by

traffic, re-verified, and automatically rolled back to the previous revision
if either check fails. It finishes by refreshing the free-fleet VM's
`kiwidaemon:latest` and restarting `kiwi-daemon-image.service` +
`kiwi-provisioner.service`.

This Terraform module still owns *provisioning* — creating the services,
networking, and IAM the first time, or changing their shape (env vars,
scaling, secrets). Routine version bumps go through `deploy.yml`, not
`terraform apply`.

One-time setup for the pipeline's GCP credentials (Workload Identity
Federation, a scoped deploy service account) lives in
[`deploy/gcp/bootstrap-cicd.sh`](../bootstrap-cicd.sh); run it once, then set
the `GCP_WORKLOAD_IDENTITY_PROVIDER`, `GCP_DEPLOY_SA_EMAIL`, and
`POSTHOG_KEY` GitHub Actions repo secrets it prints.

**Manual override:** the steps in the runbook above still work for an
emergency out-of-band deploy — `deploy.yml` is a wrapper around the same
`gcloud` commands, not a replacement for knowing them.
